# Day 34 - Contextual Logging with Winston & AsyncLocalStorage

**Level**: Intermediate  
**Date**: October 8, 2026  
**Status**: ✅ Completed

## Objective
Establish structured, production-grade observability across all layers of the application using **Winston** and Node.js **`AsyncLocalStorage`**. Every log entry must automatically record `requestId`, `userId`, and execution metadata without explicitly plumbing request objects through domain services, while deep redaction guarantees sensitive credentials are never leaked.

## Key Learnings
- **Request Context via `AsyncLocalStorage`**: By wrapping each request lifecycle in an `AsyncLocalStorage` store within the `requestId` middleware, context stays accessible across arbitrary `await` boundaries without polluting domain function signatures.
- **Dynamic Context Augmentation**: Calling `addToLogContext({ userId: user.id })` immediately after JWT verification transparently annotates all subsequent log entries generated by services or repositories during that request.
- **Deep Recursive Redaction**: Writing a dedicated Winston format that traverses log metadata objects and masks sensitive keys (`password`, `token`, `refreshToken`, `cookie`, `apiKey`, `authorization`) at any nesting depth prevents catastrophic credential leaks into centralized log aggregation.
- **Modular Child Loggers**: Utilizing `logger.child({ component: 'OrderService' })` allows individual modules to attach static metadata while inheriting the dynamic request context seamlessly.
- **Parameterized Route Logging**: Logging Express route patterns (`/api/orders/:id`) rather than raw request URLs with concrete IDs keeps metrics and log queries cleanly groupable in monitoring systems.
- **Environment-Adaptive Log Levels**: Configuring debug output for local development, JSON-formatted info logs for production, and error-only output during test suites keeps outputs actionable and fast.

## Log Context Architecture

```typescript
// @restful/shared - log-context.ts
import { AsyncLocalStorage } from 'node:async_hooks';

export interface LogContext {
  requestId?: string;
  userId?: string;
  route?: string;
  [key: string]: unknown;
}

const asyncLocalStorage = new AsyncLocalStorage<LogContext>();

export function runWithLogContext<T>(context: LogContext, fn: () => T): T {
  return asyncLocalStorage.run(context, fn);
}

export function addToLogContext(fields: Partial<LogContext>): void {
  const store = asyncLocalStorage.getStore();
  if (store) {
    Object.assign(store, fields);
  }
}

export function getLogContext(): LogContext {
  return asyncLocalStorage.getStore() || {};
}
```

### Challenges Faced & Solved
- **String Interpolation Bypassing Redaction**: Redaction formats can reliably inspect structured metadata objects, but cannot easily redact credentials concatenated directly into log message strings (e.g. `logger.info(\`User logged in with password \${pass}\`)`). I enforced a strict rule that message strings must remain static descriptions, moving all variable data into structured metadata payloads.
- **Response `finish` Event Context Disconnect**: Express's `res.on('finish', ...)` callback can run outside the original async store execution frame depending on Node event loop scheduling. To prevent missing `requestId` in request completion lines, the response logger captures the context reference synchronously during middleware setup.
- **Cross-Request Context Isolation**: Verified with concurrency tests firing simultaneous HTTP requests to ensure no request ever logs another concurrent request's `requestId` or `userId`.
